# ADR 0002: импорт GeoNames фильтруется по типу населённого пункта, не по размеру

## Статус

Принято.

## Контекст

`cities500.txt` — не только про города: это geoname-таблица GeoNames,
отфильтрованная поставщиком по критерию «население ≥ 500 ИЛИ является
административным центром», но `feature_code` в ней разнообразный — от
`PPLC` (столица) и `PPLA`…`PPLA5` (административные центры разных уровней)
до `PPLQ`/`PPLW`/`PPLH` (заброшенные/уничтоженные/переставшие существовать
населённые пункты) и `STLMT` (settlement — не начинается с `PPL`, всего
48 из 235093 строк дампа).

При подготовке импорта возник вопрос: как отсекать «мусор» — записи, не
являющиеся действующим населённым пунктом, — не отсекая заодно маленькие
реальные посёлки. Два разных критерия смешивались в один: «выглядит ли
это населённым пунктом» (тип) и «достаточно ли это крупно» (размер).

## Решение

Фильтруем по `feature_code`: оставляем только коды, начинающиеся с `PPL`
(populated place), и явно исключаем `PPLQ` (abandoned), `PPLW`
(destroyed), `PPLH` (historical — существовавший, но переставший быть
населённым пунктом). Population `population` **не участвует** в критерии
включения/исключения строки — маленький посёлок с населением в несколько
сотен человек загружается наравне со столицей. См.
`scripts/import_geonames.py` (`_is_populated_place`) и
`migrations/001_cities.sql` (`idx_cities_feature_code`).

На реальном дампе (`cities500.txt`, 235093 строки) это исключает 125
строк: 41 `PPLQ` + 27 `PPLH` + 9 `PPLW` + 48 `STLMT` (не начинается с
`PPL`); 234968 строк остаются, включая все населённые пункты с населением
от нескольких сотен человек.

## Обоснование

- **Тип и размер — разные вопросы.** Фильтр по типу отвечает на вопрос
  «это вообще место, где живут люди, сейчас?» — и должен отсекать записи,
  для которых ответ буквально «нет» (заброшено, уничтожено, не
  существует). Фильтр по размеру отвечает на другой вопрос — «достаточно
  ли это крупно, чтобы быть значимым?» — и в контексте автодополнения для
  ввода места рождения этот вопрос не должен решаться сервисом вместо
  пользователя.
- **У маленького посёлка есть законное место в справочнике.** Сервис
  используется для ввода места рождения человека — а родиться можно и в
  посёлке в несколько сотен жителей. Отсечение по населению превратило бы
  «не нашли в автодополнении» в реальный отказ в обслуживании для части
  пользователей, у которых нет более удобной альтернативы (в отличие от
  внешнего геокодера, здесь список мест — это весь функционал ввода места
  рождения, а не вспомогательная подсказка).
- **`cities500.txt` уже прошёл предфильтрацию поставщика.** Файл и так не
  включает вообще все ~12 млн точек GeoNames — только те, что либо
  крупнее порога, либо являются административным центром. Пороговая
  фильтрация на этом уровне уже сделана GeoNames; накладывать свою поверх
  означало бы вырезать из уже урезанного набора без дополнительной пользы.
- **`PPLQ`/`PPLW`/`PPLH` — это не про размер, а про существование.**
  Исключение этих кодов — не эквивалент фильтра по размеру: маленький, но
  существующий посёлок (`PPL`, население 500+) остаётся; крупный, но
  уничтоженный (например, после стихийного бедствия) — не остаётся,
  сколько бы человек там ни жило до этого.

## Последствия

- Справочник больше (234968 строк вместо гипотетически урезанного по
  порогу населения набора) — это ожидаемо увеличивает размер таблиц и
  индексов, но не меняет порядок величины (десятки/сотни тысяч строк —
  всё ещё тривиально для PostgreSQL с индексами из
  `migrations/001_cities.sql`/`002_trigram_search.sql`).
- Ранжирование результатов автодополнения по-прежнему сортирует по
  населению (`ORDER BY ... population DESC`, см. `city_repository.py`) —
  маленькие посёлки не пропадают из справочника, но и не оттесняют
  крупные города в выдаче при неоднозначном запросе.
- `feature_code` не используется для фильтрации на уровне запроса (в
  `cities` он уже гарантированно только «населённый пункт») — индекс
  `idx_cities_feature_code` нужен для операционных/аналитических запросов
  (см. `migrations/001_cities.sql`), а не для самого поиска.
